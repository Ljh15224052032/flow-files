## 1. 自动预检

在仓库根目录运行：

```powershell
.\tools\Test-ReleaseReadiness.ps1
```

脚本必须全部通过：四处版本号一致、前端测试、生产构建、Rust 后端测试以及 `git diff --check`。只排查前端问题时可以临时使用 `-SkipRust`，但它不能作为发布依据。

生成本机签名候选安装包时运行：

```powershell
.\tools\Build-SignedInstaller.ps1
```

脚本从当前用户的 `.tauri` 目录读取私钥和 DPAPI 加密的密码备份，密钥只进入构建进程环境，不打印也不写入仓库。输出会列出安装包、更新签名和 SHA-256。该签名用于 Tauri 更新器验证；Windows 安装包本身若未配置代码签名证书，仍可能显示 SmartScreen 提示。

构建后使用实际输出的路径和 SHA-256 做静态验收：

```powershell
.\tools\Test-InstallerCandidate.ps1 `
  -InstallerPath 'C:\path\to\Flow Files_0.2.0_x64-setup.exe' `
  -ExpectedVersion '0.2.0' `
  -ExpectedSha256 '<Build-SignedInstaller 输出的哈希>'
```

构建脚本默认拒绝脏工作区，并在安装包旁生成 `.candidate.json`，记录完整 Git 提交、安装包与更新签名的哈希、稳定应用标识和安装模式。静态验收会重新核对该清单、四处项目版本、安装包产品元数据、文件哈希、`.sig` 是否为可解码的 Tauri minisign 信封，以及签名内记录的文件名和版本。它不能替代更新器运行时的公钥验签，也不能替代下方实机安装矩阵。`WindowsCodeSignature=NotSigned` 表示尚未购买 Windows 代码签名证书，与 Tauri 更新签名是两套不同机制。

## 2. 测试环境

为避免影响日常使用，优先在 Windows Sandbox、测试账户或虚拟机执行。实机测试前先退出正在运行的 Flow Files，并备份以下数据：

- `%LOCALAPPDATA%\com.coderebuild.filemanagerlab`（WebView 本地状态；这是当前实际持久化位置）
- Windows 凭据管理器中由 Flow Files 创建的 Claude/DeepSeek 配置
- 当前桌面和开始菜单快捷方式的截图或记录

安装包只应来自 GitHub Release；核对发布者、版本和 SHA-256 后再运行。不要关闭 SmartScreen、杀毒软件或系统安全策略来“让测试通过”。

## 4. 发布判定

以下任意一项失败都不应公开草稿 Release：

- 安装或覆盖升级破坏用户文件、收藏、标签或设置。
- 更新器绕过用户确认，或未验证签名即安装。
- 卸载影响 Flow Files 目录以外的文件。
- 核心文件操作出现数据损坏、无提示失败或无法恢复的卡死。

通过后，将表格中的“未执行”改为“通过”，补充测试环境和异常说明，再把 GitHub 草稿 Release 改为公开。应用内更新只面向公开 Release，因此公开前仍需先完成安装包验收。
